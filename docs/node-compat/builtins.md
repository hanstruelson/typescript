# Native JavaScript built-ins

Node module expansion is paused while the shared JavaScript built-ins are implemented and checked against Node. Goja is permitted at the regular-expression boundary, including regex-dependent string operations; ordinary built-ins and primitive conversions must be native.

The [API inventory](builtins-api.json) records the Node reference surface, including symbol-named entries. Presence in this inventory does not imply implementation or conformance. The behavioral references are [ECMA-262](https://tc39.es/ecma262/) and, for locale formatting, [ECMA-402](https://tc39.es/ecma402/). RFC date formats alone do not define JavaScript Date behavior.

## Property storage and performance

Ordinary data properties stay in the existing value map. Descriptor metadata is allocated when needed, rather than wrapping every value in an accessor object. Accessors receive the original receiver through inherited lookup. Enumeration checks the enumerable flag; JSON uses the same reads and enumeration as Object operations. DefineProperties converts all descriptors before beginning writes.

Concrete class field lenses continue to refer directly to native Go fields. Their readField and writeField callbacks have separate names and calling conventions from dynamic JavaScript getters and setters. Descriptor redefinition of those concrete fields is not yet supported; this is an explicit compatibility gap, not a silent representation change.

## Date and locale data

Date stores milliseconds as a float64 internally and clips at ±8.64e15. Native time-zone conversion resolves repeated local times to the earlier instant and advances nonexistent local times by the transition gap. UTC construction never round-trips through the local zone. Time-zone locations are cached, and UTC conversion avoids transition searches.

The standalone date parser is adapted from Goja's Go source, with [its license retained](goja-date-parser-LICENSE.txt). It does not invoke or embed a Goja runtime.

The initial locale data supports English US/UK Gregorian patterns, component options, date/time styles, hour cycles, fractional seconds and time-zone names. Patterns are generated by tools/generate-date-locales.mjs during development; emitted programs use native Go formatting and never invoke Node. Further locale data and internationalization behavior remain unfinished. This is not a claim of perfect Date or full Intl compatibility.

## Validation

Compiler tests compare Date construction, parsing, every getter/setter, clipping/overflow, primitive conversion and formatting against Node in UTC, America/New_York and Australia/Lord_Howe. Locale tests compare English US/UK options and metadata. Object/JSON tests cover receivers, inherited accessors, descriptor conversion order, UTF-16 surrogates, revivers, raw JSON, function identity and cycle errors. Generated programs run with Go's race detector. Runtime boundary checks reject accidental Go interface boxing.

The filesystem implementation remains in progress and HTTP is deferred.
